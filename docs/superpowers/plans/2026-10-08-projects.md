# Projects (TFG-34) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add board-scoped Projects (Linear-style planning layer above tasks) with REST + MCP + WebSocket surfaces and web UI (sidebar routes, project pages, task pickers).

**Architecture:** New `Project` Prisma model + nullable `Task.projectId` (`SetNull`). New `projects/` NestJS module copied from the `views/` pattern (controller/service/module/dto, `MembersService.isBoardAdmin` gating + legacy-board fallback). MCP gets a `projects_*` tool group delegating to `ProjectsService`. Web gets `use-projects.ts` hook + two sidebar routes + picker in task dialogs.

**Tech Stack:** NestJS 11, Prisma 6 + SQLite, Socket.IO (RxJS Subject), React 19 + React Query + Vite. API CommonJS `strict:false`, web ESM `strict:true`.

**Spec:** `docs/superpowers/specs/2026-10-08-projects-design.md` (implements TFG-34).

## Global Constraints

- API is CommonJS; web is ESM — never copy import patterns between apps.
- `apps/api/tsconfig.json` stays `strict: false`. Do not add strict mode.
- No Prisma enums — `status` is a String validated against `PROJECT_STATUSES` const + `@IsIn` in DTOs (views precedent).
- Acid Lime (`--primary`) is one primary CTA per screen. Progress bars are neutral: Obsidian/Charcoal fill + inset Graphite border. No gradients, no new accent colors. Inter Variable ≤ 590 weight.
- Reads stay unscoped (any authenticated user). Writes gate: board admin (global admin passes) OR legacy board (zero Member rows) — the `ViewsService` pattern. Never gate reads.
- Activity diffs must use `!== undefined` (null-safe), never bare truthy checks on nullable fields.
- PrismaModule is `@Global()`; feature modules import only `EventsModule` (+ `MembersModule`) and export their service for MCP.
- Filenames kebab-case. Tests are integration-level against a temp SQLite DB (`createTestPrisma()`); each spec file cleans tables in `afterEach` in reverse dependency order.
- New migration must be committed (docker-entrypoint runs `migrate deploy`).
- Format with `pnpm format` (prettier, print width 100, single quotes) before committing.

## Review Focus

1. **`projectId: null` un-assignment** — must log `task_removed_from_project` activity and emit events; a truthy-check regression silently drops the activity row (the exact bug class TFG-56/publish hit). Pinned by Task 3 tests.
2. **Cross-board assignment** — assigning a task to a project on a _different_ board must 400, not silently re-board. Pinned by Task 2/3 tests.
3. **Cancelled tasks vs completion** — `completed` rollup counts `status.type === 'done'` only; cancelled/duplicate/blocked counts must not inflate completion. Pinned by Task 2 test.
4. **Write gating matrix** — plain `member` rejected, `admin` member allowed, global admin (`user.role === 'admin'`) allowed, zero-Member legacy board allowed. Pinned by Task 2 tests.
5. **`completedAt` lifecycle** — stamped exactly when status enters `completed`, cleared when leaving, untouched by edits that don't change status. Pinned by Task 2 test.

```prisma
model Project {
  id          String    @id @default(cuid())
  boardId     String
  name        String
  description String?
  icon        String    @default("📦")
  leadId      String?
  status      String    @default("planned") // planned | started | completed | paused | canceled
  completedAt DateTime?
  startDate   DateTime?
  targetDate  DateTime?
  position    Float     @default(0)
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt

  board  Board  @relation(fields: [boardId], references: [id], onDelete: Cascade)
  lead   User?  @relation("ProjectLead", fields: [leadId], references: [id], onDelete: SetNull)
  tasks  Task[]

  @@index([boardId, status])
  @@index([boardId, position])
  @@map("projects")
}
```

- Write gating: private `assertCanMutateBoard(boardId, user)` → throws `ForbiddenException` unless `members.isBoardAdmin(boardId, user.id)` or legacy board (`member.count({ where: { boardId } }) === 0`). Reads unscoped.
